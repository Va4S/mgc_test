# Система управления пользователями

Веб-приложение с входом по логину и паролю, двумя ролями и управлением пользователями.

- Сервер: Python, FastAPI, SQLAlchemy
- Интерфейс: React, TypeScript, Vite
- База данных: PostgreSQL 16

## Возможности

- Вход по логину и паролю, кнопка «Выйти».
- Две вкладки: «Главная» и «Пользователи».
- Администратор создаёт, изменяет и удаляет пользователей.
- Сотрудник видит только список пользователей.
- Список работает через постраничную загрузку (по 20 записей) и поиск на стороне сервера, поэтому остаётся быстрым при тысячах записей.

## Запуск

Нужны Linux или macOS, установленные Docker с плагином Docker Compose, `openssl` и `git`.

1. Скачайте проект и перейдите в его папку:

   ```sh
   git clone <адрес репозитория>
   cd <папка проекта>
   ```

2. Создайте файл с настройками `.env`. Пароль базы данных и ключ подписи токенов сгенерируются случайно, пароль администратора задаётся командой ниже:

   ```sh
   ADMIN_PASSWORD='Admin-Start-2026' sh scripts/init-env.sh
   ```

3. Запустите проект:

   ```sh
   docker compose up -d --build
   ```

4. Откройте в браузере http://localhost:8080

**Администратор по умолчанию**

| Логин | Пароль |
|-------|--------|
| `admin` | `Admin-Start-2026` |

Пароль — это значение, которое вы передали в шаге 2. Если указать другое значение, войти нужно будет с ним. Администратор создаётся при первом запуске, если пользователя с таким логином ещё нет.

Остановить проект: `docker compose down`. Данные сохраняются в томе Docker. Чтобы удалить и их: `docker compose down -v`.

## Запуск в режиме разработки

Дополнительно нужны Python 3.12+ и Node.js 20+.

1. Создайте `.env` (шаг 2 из раздела «Запуск»), если его ещё нет.

2. Запустите только базу данных, открытую на localhost:

   ```sh
   docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d db
   ```

3. Запустите сервер (первый терминал):

   ```sh
   cd backend
   python3 -m venv .venv
   . .venv/bin/activate
   pip install -r requirements.txt
   set -a; . ../.env; set +a
   uvicorn app.main:app --reload --port 8000
   ```

4. Запустите интерфейс (второй терминал):

   ```sh
   cd frontend
   npm install
   npm run dev
   ```

5. Откройте http://localhost:5173. Запросы к `/api` интерфейс сам перенаправляет на сервер. Документация API доступна по адресу http://localhost:8000/docs.

## Настройки

Все секреты хранятся только в файле `.env`, он добавлен в `.gitignore`. В репозитории лежит шаблон `.env.example` без значений.

| Переменная | Назначение |
|------------|------------|
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | Подключение к базе данных |
| `SECRET_KEY` | Ключ подписи токенов входа |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | Первый администратор |
| `APP_PORT` | Порт приложения в браузере (по умолчанию 8080) |

## Принятые решения

- **Вход и выход.** После входа сервер выдаёт токен на 12 часов, интерфейс хранит его в браузере. Выход удаляет токен в браузере.
- **Права доступа** проверяются на сервере: сотрудник получает ошибку 403 при попытке создать, изменить или удалить пользователя, даже если обратится к API напрямую. В интерфейсе кнопки управления для сотрудника скрыты.
- **Вкладка «Пользователи»** доступна обеим ролям, у сотрудника она работает только на просмотр.
- **Защита от потери доступа.** Администратор не может удалить себя или снять с себя роль администратора.
- **Логин** уникален, допускает латинские буквы, цифры и символы `_ . -`, длина от 3 до 50. **Пароль** — от 8 до 72 символов, хранится в виде bcrypt-хеша.
- **Изменение пользователя.** Пароль меняется только если поле заполнено.
- **Таблицы** создаются сервером автоматически при первом запуске, отдельные миграции не используются.
- **Поиск** ищет по имени и логину без учёта регистра.

```
backend/    сервер (app/routes.py — API, app/models.py — модель, app/main.py — запуск)
frontend/   интерфейс (src/pages — страницы, src/components — окна, src/api.ts — запросы)
scripts/    создание файла настроек
docker-compose.yml       запуск проекта
docker-compose.dev.yml   дополнение для разработки
```
